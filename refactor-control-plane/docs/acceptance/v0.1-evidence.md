## 新鲜验证要求

每次发布或完成声明都必须重新执行：

同一交付中已通过且代码未变化的检查可以复用；外部中断后核对逐类报告，只补齐未完成项和受新修改影响的检查，并记录实际日期及覆盖范围，不虚构一次完整运行成功。

1. 后端 `mvn verify`。
2. 前端 `npm test`、`npm run typecheck`、`npm run build`。
3. 启动后端并读取 `/actuator/health`、`/api/v1/demo/overview`、`/mcp`。
4. 启动前端，以实际身份验收项目导入/计划、分配/执行、冲突/验证、审批/导出和文章切片；静态八角色切换不能代替权限与操作验收。
5. `git diff --check`，并确认父工作区无关改动未被纳入提交。
6. 对照 12 项基线保留仓库/基线与候选 SHA、执行与证据身份、命令输出、角色及审批、main 前后状态和未解决风险。文档-only 校对只做结构/链接/差异检查，不据此产生新的产品 PASS。

## 生产化边界

v0.1 是单项目、单节点参考实现。H2、本地角色模拟和进程内租约不是多节点生产部署方案；生产落地必须替换为受管数据库/分布式租约、OIDC/LDAP、TLS 与集中审计。此边界不改变 MVP 的人工合并、源码不出内网和条件写入不变量。
