# MVP 可执行验收基线

| ID | 场景 | 验收结果 |
|---|---|---|
| MVP-01 | 导入缺少架构文档的遗留仓库 | 生成技术栈、模块、依赖和证据化架构视图 |
| MVP-02 | 为文章管理切片制定迁移计划 | 生成带依赖、资源和验收契约的工作包 DAG |
| MVP-03 | 三个无冲突任务同时就绪 | 创建三个独立 worktree/branch 并并发执行 |
| MVP-04 | 两个任务申请不兼容路径租约 | 后到任务不被错误调度，并获得明确阻塞原因 |
| MVP-05 | 上游发布破坏性 API 或 Schema 变化 | 相关下游执行自动进入 `STALE` |
| MVP-06 | 智能体提交超出授权范围的修改 | 提交被拒绝并产生审计事件 |
| MVP-07 | 多分支存在文本或语义冲突 | Integration AI 输出冲突证据、影响任务和建议顺序 |
| MVP-08 | 文章管理完成 Vue 3 + Spring Boot 迁移 | 功能对照、API 契约、数据库兼容和测试证据齐全 |
| MVP-09 | Review 或测试门禁未通过 | 工作包不得进入 `ACCEPTED` |
| MVP-10 | 所有门禁和审批通过 | 仅生成可人工合并建议，不自动更新 `main` |
| MVP-11 | Git/数据库提交过程中断或并发竞争 | 重试幂等、并发胜者不被覆盖、对账结果一致 |
| MVP-12 | 审计角色导出项目记录 | 报告包含决策、任务、模型、变更、测试、审批和风险链路 |

## 首批自动化场景

1. 工作包合法与非法状态转换。
2. 独占租约冲突与过期租约回收。
3. Context/API/Schema 版本变化触发任务失效。
4. 幂等提交不产生重复 Change Event。
5. 未通过必需 Gate 时拒绝接受任务。
