# 第 8 里程碑：执行与恢复验收

验收日期：2026-10-13。范围是单节点控制平台的 Mock/HTTP 执行、容量与路径租约、提交授权及恢复。企业开发智能体、质量证据内容核验和完整 MVP 发布不在本次完成声明内。

## 可复现检查

在 `backend` 目录使用 Java 21、Git 及项目现有 Maven 依赖：

```powershell
mvn.cmd --% -o -s ../scripts/maven-offline-settings.xml -Dmaven.repo.local=.m2-repository -Dtest=ExecutorConcurrencyAcceptanceTest,TaskExecutorApiContractTest verify -l ../.runtime/phase8c-final.log
```

离线命令要求本项目依赖缓存已准备好；不更改全局 Maven、Git、Java 或网络配置。夹具自行创建临时仓库、文件 H2、本机 HTTP 服务和真实检查子进程，结束后关闭进程与数据库。每次运行生成 `backend/target/phase8c-evidence.json`，本轮留档见[执行身份与时间证据](milestone8-execution-evidence.json)。随机 SHA、执行 ID 和 PID 每次不同，不能硬编码为通过条件。

## 退出条件与证据

| 条件 | 实际验证 |
|---|---|
| 三个任务真实并发执行 | 两个本机 Mock，加一个经 HTTP 调度、使用独立执行数据库的真实 Mock 工作者；各自修改独立工作树、创建 Git 提交，并启动独立 JVM 检查进程 |
| 运行区间确实重叠 | 三个检查进程分别原子发布开始时间与 PID，全部到达屏障且仍存活后才释放；断言最晚开始早于最早结束，不以创建三个工作树代替并发 |
| 检查与提交有效 | 每个进程读取本任务的实际输出并核对内容，再执行 `git diff --check HEAD~1 HEAD`；最终检查两项结果、SUBMITTED 状态、分支 HEAD、固定父提交和仅一个任务提交 |
| 容量不足阻断 | 三个运行任务占满负责人和环境的三个槽位；第四个领取被拒绝，两个阻断原因可见，Git 工作树列表不变 |
| 路径租约不足阻断 | 容量释放后领取路径冲突任务，投递被拒绝，保持 CLAIMED、没有受管执行记录、远端 PUT 计数不增加 |
| 丢失投递响应不重复执行 | HTTP 服务已启动真实任务后返回 503；平台保留原 ID。重复启动请求、查询和恢复之后 PUT 总数仍为 1 |
| 运行中恢复 | 两个本机任务完成、HTTP 检查进程仍运行时重建平台运行时并重新打开文件 H2；保留 HTTP 执行 ID 与容量，继续查询原任务 |
| 持久写入后的响应丢失 | 注入 `audit_event` complete 已成功落库、调用方收到异常的边界；再次重建后恢复成功提交，不重复投递或生成第二个提交 |
| 越权结果拒绝 | HTTP 工作树真实提交含禁止目录的文件，即使服务报告 SUCCEEDED 也拒绝提交；commitSha 未发布、容量保留，FAILED 审计记录增加 |
| 迟到结果不污染新执行 | 先阻塞旧执行真实 GET 响应，确认其仍在途；项目经理确认停止并重新领取后才释放响应。原运行保持 STOPPED，新执行 ID 和 CLAIMED 状态保持不变 |
| 旧凭据拒绝 | 停止与重试后，旧任务令牌调用 MCP 得到授权拒绝，不能把新执行标记为阻塞 |
| main 不变 | 三个提交均留在任务分支；证据中的 mainAfter 与固定 baseCommit 完全相同 |

8B 接口回归另外覆盖未登录投递拒绝、票据绑定错误、重复启动幂等、状态失联/恢复、租约过期重取及竞争租约保留、投递在途停止拒绝。相关配置与协议见[任务执行器](../task-executors.md)。

## 验证边界

HTTP 执行端使用本机真实工作者夹具，经过实际 HTTP 请求和共享文件系统；它不是已连接的企业智能体服务。两个本机 Mock 与 HTTP 工作者都执行真实 Git 和检查命令，平台按已有授权与日志机制接收结果。本轮没有改动生产执行代码或前端。

恢复覆盖文件 H2 关闭/重开、运行时重建，以及持久完成后响应丢失的故障注入；不将其描述为操作系统断电、数据库损坏、强杀整台服务或多节点故障耐久性认证。HTTP 服务的检查摘要仍是可信服务声明，独立内容证据、模型记录与审计导出按第 9 里程碑推进。
