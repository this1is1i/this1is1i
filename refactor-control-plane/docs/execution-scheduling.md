# 执行容量与第 8 里程碑

2026-10-13：8A 容量准入、8B Mock/HTTP 执行器与 8C 三执行器并发/恢复验收均已完成。[验收记录](acceptance/milestone8-execution.md)列出复现命令、具体故障边界及未覆盖的生产化范围。

## 已确认的执行边界

用户选择 **A：内网执行服务直接操作平台分配的独立工作树**，通过执行 ID 查询进度与结果。平台继续负责授权、任务版本、路径租约、提交校验和人工门禁；执行服务需要访问分配的工作区。工作树是 Git 隔离边界，并非操作系统安全沙箱。

HTTP 协议先持久化投递标识，再提交外部任务；超时进入结果未知状态，先查询同一执行 ID，不能直接创建下一次执行。重复结果和迟到结果必须匹配当前执行、分配轮次及语义版本。配置与接入协议见[任务执行器](task-executors.md)；ModelGateway 仍只处理模型文本请求。

## 配置容量

在[项目定义](project-plans.md)顶层加入可选 `scheduling`：

```json
{
  "scheduling": {
    "actorCapacities": { "developer": 2, "agent-internal": 1 },
    "environmentCapacities": { "test-db": 2 }
  }
}
```

这里是需要并入完整计划的片段。`actorCapacities` 的键是任务负责人的主体 ID；它不创建账号，也不授权该主体访问项目。`environmentCapacities` 的键必须与 `resources` 中全部 `ENVIRONMENT` 类型资源的 ID 完全对应。任务通过已有 `taskResources` 声明使用哪些环境；每次执行占用一个负责人的槽位以及每个声明环境各一个槽位。

- 容量只接受 1–1000 的 JSON 整数；拒绝字符串、小数、零、缺失环境和非环境资源。
- 启用调度后，未配置容量的负责人不能领取；工作台显示容量为 0 的阻断原因。
- 容量属于计划指纹。修改需要计划修订、架构师与独立项目经理重新确认、激活并重启，不能编辑已批准文件绕过审批。
- 旧计划省略 `scheduling` 时保持原行为，不自动增补字段或改变其指纹。旧计划不会凭空获得容量限制；应显式升级计划后使用该功能。
- 同一物理环境只应声明一个资源 ID，版本和 locator 是描述信息；当前不通过 locator 自动识别资源别名。

## 占用与释放

| 事件 | 容量行为 |
|---|---|
| 领取 READY 任务 | 在创建工作树前，在同一运行时锁中同时检查所有容量；任一不足即拒绝，不创建额外工作树 |
| 成功领取 | 执行 ID 随已有操作日志持久化；由已恢复执行推导占用，不维护另一份易失计数器 |
| 提交真实 changeset 且授权通过 | 本次人工/MCP 执行视为已结束，释放计算及环境槽位；路径租约继续按现有治理规则管理 |
| BLOCKED、STALE、CANCELLED、路径租约过期或重启 | 不证明执行进程已停止，保留容量 |
| 独立项目经理确认本次执行已停止 | 持久化停止证据、释放容量与路径租约并轮换任务凭据；CLAIMED/RUNNING 转为 BLOCKED |
| 重新执行、语义重绑定或切换计划 | 启用调度时，未提交执行必须先完成停止确认；不能借重试或计划切换丢弃占用 |

容量准入不替代路径租约。人工领取后通过 MCP 申请授权范围内的写租约；受管执行器由平台投递前取得独占租约，提交时同样校验真实 Git diff。当前没有自动排队、公平性/优先级算法、跨节点容量协调或操作系统进程限制。

## 工作台与停止对账

工作包展示 `capacityBlockers`：`kind` 为 ACTOR/ENVIRONMENT，另含 `resourceId`、`capacity`、`used`。`capacityHeld` 表示该任务当前执行仍占用已配置容量。`get_ready_tasks` 和工作台 `claimable` 同时考虑容量约束。

独立项目经理在工作台填写停止核对证据后，使用“确认已停止并释放容量”。必须先在实际执行环境核对进程已退出或远端任务已终止；这个操作不发送终止信号，也不验证引用内容的真实性。完整证据校验属于第 9 里程碑。

对应治理请求：

```json
{
  "action": "confirm_execution_stopped",
  "taskId": "CAT-1",
  "taskExecutionId": "本次执行的完整 ID",
  "evidenceRef": "process-log:已核对退出记录",
  "expectedVersion": 1,
  "idempotencyKey": "唯一且可重试的操作键"
}
```

入口为 `POST /api/v1/governance/commands`，使用项目经理的 Bearer 凭据。要求主体不同于任务负责人，执行 ID 精确匹配当前执行，且任务处于 CLAIMED/RUNNING/BLOCKED/STALE/CANCELLED。旧执行 ID、错误角色或无证据请求被拒绝。重复请求复用原幂等键；确认结果未知时先刷新核对，不使用新键盲目重复提交。

停止确认不修改、删除旧工作树或提交；后续重试创建新的执行 ID。旧凭据无法再通过平台授权，但平台不能阻止已经持有文件系统权限的进程继续写磁盘，因此必须先核对真实停止状态。
