## 第一期：核心治理升级

- 服务端项目身份、任务分配和独立人工审批；执行者不能自报角色或跳过门禁。
- 实际领取创建独立 Git branch/worktree；真实 SHA、仓库身份、基线祖先、diff、路径权限和有效租约共同约束提交。
- 审批和合并建议绑定执行 ID 与提交 SHA；旧验收历史与当前有效性分离。
- READY 查询与领取均检查 DAG 前置验收；语义变化传播到所有下游，重验证更新不可变版本并生成新执行，旧令牌撤销。
- 租约归属从服务端绑定，拒绝跨任务释放与终态续租；拒绝有损规范化的 Git 文件路径。
- PENDING 中先保存 Git 执行计划，COMPLETED 中保存状态投影；完成记录成功后才发布内存状态，日志不确定时冻结写入等待重启对账。
- 兼容旧操作日志，旧审批与未绑定 Git 的执行标记未验证；过期心跳不会永久阻断启动。
- 项目经理可对 BLOCKED / REJECTED 任务发起新尝试；旧分支和目录保留，不自动覆盖。

配置与 API 用法见[本地治理操作说明](governance-operations.md)。默认没有启用账号，需显式配置本项目身份文件。

## 已知边界

- 当前主机具备 Java 21、Maven 3.9.2、Node 22 和 npm 10。
- 前端依赖已锁定在 `package-lock.json`；项目要求 Node 22.12 以上且低于 23。
- 样例项目使用 Java 7 时代工具链，后续需要独立 legacy runner，不能依赖控制平面的 Java 21 运行时直接启动。
- v0.1 是单项目、单节点参考实现；生产多节点部署需要外部一致性存储和分布式租约。
- Maven 首次执行需在项目内使用 `backend/.m2-repository`；PowerShell 调用批处理入口时应使用停止解析标记确保 `-D` 参数不丢失。
- 父工作区存在与本项目无关的用户改动；不得修改或清理。
