# 真实集成工作台

工作台读取服务端任务、执行提交、质量门禁、有效路径租约、变更事件和集成候选。左侧八类角色仅用于查看职责，实际身份与权限来自项目访问凭据；页面不再用固定指标冒充执行结果。

## 连接与使用

1. 按[本地治理说明](governance-operations.md)配置项目身份，按[集成候选说明](integration-candidates.md)配置本机验证命令。没有配置身份不能操作；没有验证方案不能创建候选。
2. 打开前端，在“项目访问凭据”中输入当前人员的 Bearer token。凭据只保存在页面内存中，不写入浏览器存储或 URL；退出、刷新页面后需要重新连接。
3. 工程负责人勾选已提交的任务，页面显示自动补齐的完整依赖集合。创建后选择候选，核对源提交、目标基线、组合指纹及冲突证据。
4. 独立 QA 负责人连接后运行组合验证。检查结果显示退出码、超时、截断提示和输出日志；本机执行只适用于可信代码，验证范围取决于项目配置的检查。
5. 所有输入任务验收完成、最新组合验证通过且候选仍有效时，独立工程负责人可生成人工合并建议。建议绑定候选 SHA 与验证 ID，平台不执行最终合并。

工作包区域提供按权限开放的评审、测试、门禁记录、验收、返工及语义重验证入口。记录门禁必须填写证据引用，当前版本不会核验引用指向的报告内容。任务分配、领取、路径预留和代码提交继续使用治理 API / Project MCP。

## 状态与失败处理

- 使用“刷新状态”读取最新状态；当前没有后台轮询。刷新失败或候选状态未确认时，写操作禁用。服务端在写操作时再次核对版本及真实 Git 状态。
- 目标引用、源执行、语义版本或验证方案变化会使旧候选过期。历史 PASS 仍可查看，但不能再生成有效合并建议。
- 写请求的网络失败、5xx 或 409 可能发生在服务端已经保存计划之后。页面保留原始请求与幂等键，重试复用同一请求，不新建另一轮执行。
- 可先刷新核对结果，再显式结束本页重试记录；这不会取消服务端操作。退出或刷新整个页面也不会取消操作，但会清除本页内存中的重试记录，重新连接后应先检查候选和验证状态。
- `RUNNING` 记录表示执行中或完成情况未知；服务中断后需维护者检查对应验证目录，不能自动重跑未知执行。
- 切换身份、候选或刷新时，迟到的旧响应不能覆盖新的页面状态；创建期间手动选择其他候选，完成结果不会强制跳回。

## 读取接口

`GET /api/v1/workbench` 使用项目成员 Bearer 身份，并返回 `Cache-Control: no-store`。数据包括项目和主体 ID、真实角色、上下文版本、任务及门禁、执行、租约、事件和验证方案摘要。方案摘要只有 ID、版本和检查 ID；该入口不返回任务令牌或执行命令参数。候选详情及验证日志沿用已鉴权的集成接口。

这是单项目、单节点工作台。实际执行隔离、指纹失效、日志恢复及人工合并边界以[集成候选说明](integration-candidates.md)为准；不代表通用重构规划、企业身份系统或旧系统业务切换已完成。
