# 真实集成工作台

工作台读取服务端任务、执行提交、质量门禁、有效路径租约、变更事件和集成候选。左侧八类角色仅用于查看职责，实际身份与权限来自项目访问凭据；页面不再用固定指标冒充执行结果。

## 连接与使用

1. 按[本地治理说明](governance-operations.md)配置项目身份，按[集成候选说明](integration-candidates.md)配置本机验证命令。没有配置身份不能操作；没有验证方案不能创建候选。
2. 打开前端，在“项目访问凭据”中输入当前人员的 Bearer token。凭据只保存在页面内存中，不写入浏览器存储或 URL；退出、刷新页面后需要重新连接。
3. 工程负责人勾选已提交的任务，页面显示自动补齐的完整依赖集合。创建后选择候选，核对源提交、目标基线、组合指纹及冲突证据。
4. 独立 QA 负责人连接后运行组合验证。检查结果显示退出码、超时、截断提示和输出日志；本机执行只适用于可信代码，验证范围取决于项目配置的检查。
5. 所有输入任务验收完成、最新组合验证通过且候选仍有效时，独立工程负责人可生成人工合并建议。建议绑定候选 SHA 与验证 ID，平台不执行最终合并。

工作包区域提供按权限开放的任务分配、领取、评审、测试、门禁记录、验收、返工及语义重验证入口。配置模式的门禁必须提交独立人工说明或当前平台验证，服务端核验内容与执行绑定；旧 demo 模式仍保留自由文本引用兼容。

第 8A 增加执行者/环境容量不足的具体原因。未完成执行保持容量占用；独立项目经理核对实际进程已停止后，可提交精确执行的停止证据并释放容量，随后进行返工或语义重验证。确认停止不会发送终止信号，详见[执行调度说明](execution-scheduling.md)。

## 任务分配与领取

项目经理连接后，在就绪任务中选择本项目成员并分配。成员目录只对项目经理返回，包含主体 ID 和角色，不含凭据摘要。没有实际执行时可以改派；已创建工作树后服务端拒绝改派，避免执行归属与现有代码分离。

负责人使用自己的项目凭据连接，在上游已验收、语义版本有效时点击“领取并创建工作树”。领取与归属校验在同一运行时锁中完成，并复用 MCP 的持久日志、执行计划和恢复流程。同一请求重试复用原执行，领取不修改 main，也不自动申请路径租约。

展开“执行信息与 MCP 接续”可查看真实执行 ID、任务分支、工作树目录、基线 SHA、允许/禁止路径以及验收命令。代码修改、租约申请/续期/释放和提交实际 SHA 继续走 Project MCP。任务凭据仍由经理通过原治理 API 带外分发；本页的分配与领取响应不返回任务令牌。页面不会启动命令行或执行所展示的验收命令。

新增接口均使用项目成员 Bearer 身份及 `Cache-Control: no-store`：

- `POST /api/v1/workbench/assign`：经理专用，参数为 `taskId`、`assignee`、正整数 `expectedVersion`、`idempotencyKey`。
- `POST /api/v1/workbench/claim`：仅当前负责人，参数为 `taskId`、正整数 `expectedVersion`、`idempotencyKey`。不接受客户端主体、角色或任务令牌字段；日志额外绑定服务端主体与分配轮次。

参数错误返回 400，身份或成员错误返回 403，版本/状态或恢复冲突返回 409。未知结果处理与候选操作相同，复用原请求核对，不反复点击新建执行。

## 状态与失败处理

- 使用“刷新状态”读取最新状态；当前没有后台轮询。刷新失败或候选状态未确认时，写操作禁用。服务端在写操作时再次核对版本及真实 Git 状态。
- 目标引用、源执行、语义版本或验证方案变化会使旧候选过期。历史 PASS 仍可查看，但不能再生成有效合并建议。
- 写请求的网络失败、5xx 或 409 可能发生在服务端已经保存计划之后。页面保留原始请求与幂等键，重试复用同一请求，不新建另一轮执行。
- 可先刷新核对结果，再显式结束本页重试记录；这不会取消服务端操作。退出或刷新整个页面也不会取消操作，但会清除本页内存中的重试记录，重新连接后应先检查候选和验证状态。
- `RUNNING` 记录表示执行中或完成情况未知；服务中断后需维护者检查对应验证目录，不能自动重跑未知执行。
- 核对后，独立 QA 可填写原因并使用“记录验证已中断”追加 ABANDONED 记录；原 RUNNING 证据保留。失效候选也支持对账，但 ABANDONED 不会通过门禁，已被新记录替代的旧 RUNNING 不再阻塞计划切换。
- 切换身份、候选或刷新时，迟到的旧响应不能覆盖新的页面状态；创建期间手动选择其他候选，完成结果不会强制跳回。

## 读取接口

配置模式现按已选 A 采集门禁证据：代码评审/业务验收填写本人说明，测试门禁使用所选候选的最新平台验证。按钮会检查本任务是否在候选内、验证是否最新及结果是否匹配；服务端再次核验精确执行、内容与当前资格。各任务可展开证据 ID；项目成员通过 `GET /api/v1/evidence/{id}` 读取。已验收任务可以更新通过证据，TESTING 阶段可续签已有通过的代码评审。自由文本测试报告不再作为配置模式放行依据，详见[证据门禁](evidence-store.md)。

`GET /api/v1/workbench` 使用项目成员 Bearer 身份，并返回 `Cache-Control: no-store`。数据包括项目和主体 ID、真实角色、上下文版本、任务及门禁、`evidenceRequired`、各任务 `gateEvidence`、可领取状态、执行、租约、事件和验证方案摘要，项目经理还可读取成员摘要。方案摘要只有 ID、版本和检查 ID；该入口不返回任务令牌或组合验证命令参数。任务自己的声明式验收命令作为执行说明展示。候选详情及验证日志沿用已鉴权的集成接口。

## 文章编辑的请求状态

文章编辑器现位于独立的 `samples/article-app` 应用；配置模式平台不注册文章接口或初始化业务表。

文章编辑器只接受最新列表响应，提交期间禁止重复写入；保存完成不会清除期间切换或修改的草稿。新增期间继续输入时，成功结果会把当前草稿接续到新文章 ID，下一次保存更新该文章。

网络中断、5xx 或新增响应缺少 ID 时，页面保留草稿并阻断继续写入；先刷新核对服务端文章，再点击“已核对结果，允许后续操作”。这里没有自动重放或跨页面持久幂等保证，整页刷新后也应先检查现有文章。保存已成功但列表刷新失败时会分别显示已保存与读取失败，避免误认为需要重新新增。

这些防线解决当前页面的请求竞态；文章 REST 接口尚未增加多用户乐观锁，不能据此承诺多个用户同时编辑不会覆盖。

这是单项目、单节点工作台。实际执行隔离、指纹失效、日志恢复及人工合并边界以[集成候选说明](integration-candidates.md)为准；不代表通用重构规划、企业身份系统或旧系统业务切换已完成。
