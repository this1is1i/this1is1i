## 已确认目标

构建一个企业级遗留系统重构控制平面，将以下阶段形成可审计闭环：

1. 项目理解与证据化架构分析。
2. 目标架构、ADR、升级风险与迁移计划。
3. 工作包 DAG、资源协调与并发调度。
4. 人工开发者或智能体在隔离任务分支中执行。
5. 代码 Review、测试、质量门禁、人工验收与证据导出。

平台不是自动重写器，不自动合并 `main`，也不把 Git 当作智能体共享语义上下文。

## 已批准约束

- 产品形态：Vue 3 Web 工作台 + Spring Boot 控制平面 + Project MCP + 可插拔执行器。
- 数据边界：代码不出内网；模型只能通过 OpenAI-compatible 企业模型网关访问。
- 执行器：首版包含 Mock 与通用 HTTP 适配器。
- 身份：首版使用本地账号模拟角色，权限模型兼容未来 OIDC/LDAP。
- 执行权限：智能体只能产出任务 branch/patch；必须人工合并。
- 隔离：每次任务执行创建独立 worktree 和 branch。
- 协作：Shared Context + Change Event + MCP 负责语义协作。
- 样例：`eyupgevenim/SpringMvcBlog`，固定 MIT License 提交
  `5e62608af333b5757bf767e05b19e2b0d56f0afb`。
- 首个重构切片：文章管理，从 JSP/Spring MVC 迁移到 Vue 3/Spring Boot。

## 不可破坏的不变量

1. Worktree/branch 按任务执行创建，不按人员永久绑定。
2. 文件锁是带 TTL、心跳、版本号的逻辑租约，不是操作系统锁。
3. 每个任务绑定不可变的 base commit、context、API contract、DB schema 和 ADR 版本。
4. 上游语义资产变化时，下游任务必须进入 `STALE` 并重新验证。
5. Integration AI 只能分析冲突和生成集成候选，不能合并 `main`。
6. 所有 AI 结论必须能追溯到源码、配置、决策或测试证据。
7. Git 与数据库跨资源写入必须幂等、使用引用前置条件，并支持状态对账；不得用失败回滚覆盖并发胜者。
8. 所有配置和依赖改动严格限制在本项目目录。

## 开发规则

- 功能与缺陷修复使用测试驱动开发；先观察预期失败，再写最小实现。
- 完成声明必须有当前轮次的新鲜构建、测试和结构校验证据。
- 保留父工作区及本项目中与当前任务无关的用户改动。
- 不直接下载或调用外部模型；公共 GitHub 样例只在显式样例初始化时下载一次。
- 文本文件统一使用 UTF-8。
- 配置计划必须绑定目标仓库、固定基线与真实验证命令；任务及集成均检查批准状态。前置任务验收不代表其产物已进入下游基线，禁止用目录创建声明代替固定 Git tree 中的工作目录证据。
- 计划修订必须重新双角色审批；激活只改数据库当前指针并要求重启，按指纹隔离旧日志、幂等键和集成成员。新基线只能来自当前通过验证且完整前置闭包已验收的候选，保留历史记录及 main。
- 配置模式不得注册业务样例接口或初始化业务表。独立样例位于 `samples/article-app`；构建/复制前解析实际子目录和输出目录，拒绝越界链接，禁止覆盖已有脚手架或重试状态不明的初始化。
- 样例初始化须在新建仓库固定本地 `core.autocrlf=false`，Windows 同时设置本地 `core.longpaths=true`。用包含真实旧源码的嵌套任务工作树及外部换行配置干扰验证清洁性；不得修改全局 Git 或系统策略，也不能仅凭仓库根检出成功判断任务工作树可用。
- 分析计算预算必须覆盖失败匹配和内部循环，不能仅限制成功结果数量；用纯空白配置、无终止符 SQL 与大量字面量验证耗时边界。源声明匹配必须排除对应语言的注释。
- 未知验证的对账只能追加带主体和原因的 ABANDONED 记录，保留原 RUNNING 证据；失效候选也要有可完成的恢复路径，禁止以对账替代通过验证。
- Git 提交授权直接基于真实 diff；若文件名不能被路径策略无损表达，必须拒绝，不能通过 trim、替换分隔符等方式把越界文件改写成允许路径。保留前导空格路径的反例测试。
- Git 子进程必须并发读取输出并保留超时与本次子进程清理；用大于管道缓冲的真实 diff 验证，禁止先等待退出再读输出。
- 日志 record、fail、结果序列化或 complete 的状态不确定时停止后续写入，重启按预先持久化的执行计划对账；不得让后续快照覆盖尚未确认的操作。
- 分析只能读取固定 Git tree/blob；禁用 replace refs 与 partial-clone 隐式抓取，用缺失对象的本机探针验证零联网，禁止运行仓库构建或补齐依赖来推导事实。
- 解析仓库清单时先限制大小、嵌套深度和外部实体，再发布事实；未知或未覆盖项必须显式保留。回归必须包含深层 XML、异常 npm 值和对象身份检查。
- 旧 posts 迁移必须显式给出来源时区、目标状态及预检指纹；只读来源，文章/映射/成功审计同事务提交，遇到目标编辑或删除保留当前状态。原始时间精度与新旧 ID 都必须有对照测试。
- OpenAPI/MCP Schema 必须对照真实响应校验；跨语言 pattern 通过 Node 独立编译，数值边界在写日志之前校验，禁止用 Java 专属正则或隐式数值转换冒充客户端契约。
- 集成候选必须覆盖完整依赖闭包，验收不等于已合入目标。仅执行项目配置的可信验证命令；候选指纹绑定真实提交组合、语义版本、目标及配置。新验证替代旧结果，未知运行不自动重放；引用发布使用 CAS，外部胜者不回滚。
- 工作台身份切换、候选切换和刷新必须屏蔽旧异步响应；读取失败禁用写入。写请求的 409 也可能发生在计划持久化之后，必须保留原请求与幂等键供核对重试；用乱序响应和持久化后失败的反例验证，禁止把未知结果当作未执行。
- 浏览器领取必须在同一运行时锁中验证当前负责人并走现有 MCP 执行日志；日志绑定服务端主体与分配轮次，分配/领取响应不暴露任务令牌。文章新增在途编辑必须接续返回 ID，选择变化不能被旧结果覆盖；结果未知时保留草稿并阻断自动重发。
- 配置容量在创建工作树前原子检查；BLOCKED/STALE/CANCELLED、租约过期和重启都不证明执行器停止。直接失联的 CLAIMED/RUNNING 必须支持独立项目经理对精确 execution ID 确认停止并转 BLOCKED、撤销凭据、释放容量；重试、重验证与计划切换不能丢弃未知占用。HTTP 适配器接入后须先按持久投递 ID 查询未知结果，不自动重发新执行。
- 证据 JSON 的摘要须在写入、持久化读取和幂等重试中使用一致的无损数值表示；以高精度十进制及大整数往返验证，禁止默认转 double 后重算内容哈希而把合法证据误判为篡改。
- 模型和语义证据必须在写 PENDING 前复用 EvidenceStore 的纯校验，检查加入平台元数据后的完整 UTF-8 字节、深度与字段边界；用合法大计划和有界 HTTP 响应反例验证不会进入永久对账循环。读取比较使用类型化或规范化值，不以 Jackson IntNode/LongNode 的运行时类型判断语义相等；有证据引用但列表为空仍须拒绝异常绑定。
- 配置模式门禁请求须核对精确 execution ID 与提交，再从当前运行时生成绑定；测试只采信平台当前候选最新验证，不能使用执行器成功摘要代替。恢复 PENDING 操作前必须安装证据及集成约束，并显式使用计划 scope，禁止依赖恢复之后才执行的服务构造器回调。
